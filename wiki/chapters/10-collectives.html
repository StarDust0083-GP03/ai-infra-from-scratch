Collective：GPU 之间怎样交换数据

源码快照 2026-09-22 · 约 10 分钟

分片后的计算只有局部结果。某一步需要完整参数，另一步只需各方贡献的和，还有一步要把 token 送到不同专家。这些数据关系由 collective 定义，NCCL 等实现负责在设备和链路上高效完成。

四个最常见操作#

AllReduce#

每个参与者提供同形状输入，按照约定操作归约，随后每方得到完整归约结果。例如 sum 用于合并梯度贡献。结果是和还是均值，取决于操作与后续缩放，不能从名称直接假定平均。

AllGather#

各方提供自己的片段，所有参与者获得按顺序组成的集合。它搬运和组合内容，不替你做逐元素加法。分片参数在某些计算前需要这种组装。

ReduceScatter#

先把各方贡献归约，再把结果拆开分给参与者。每方只留一个结果片段，可以避免人人长期保存完整归约内容，常用于分片梯度。

AllToAll#

每个源为不同目标准备不同片段，交换后各目标收到来自多个源的数据。MoE token 路由可使用这类关系。输入输出大小和分布规则需要各方匹配，数据偏斜也会影响耗时。

用两个 rank 区分归约与收集#

rank 0 输入 [2,7]，rank 1 输入 [5,1]。sum AllReduce 让双方都得到 [7,8]；AllGather 则得到按 rank 顺序排列的 [2,7,5,1]。

同样的输入做两等份 ReduceScatter，可使 rank 0 留下 [7]、rank 1 留下 [8]。若按一元素一目标做 AllToAll，rank 0 收到 [2,5]，rank 1 收到 [7,1]。这四种结果足以检查你是否把“收集”和“归约”混用。

Ring 的直觉#

一种 AllReduce 实现先通过多轮交换完成分片归约，再分发已归约片段。环中各参与者主要与邻居传输，适合利用链路带宽，但启动轮数会随参与者数量增长。

具体算法还可能采用树或其他结构。消息尺寸、拓扑和协议共同影响选择，应用通常声明数据语义，不应把某次内部使用 ring 当成永久 API 合同。

拓扑比 GPU 数量更重要#

四个参与者可能位于同一高速交换域，也可能跨两个普通以太网节点。逻辑操作相同，必要传输路径却不同。先用 nvidia-smi topo -m 等工具确认 GPU、CPU 和 NIC 的邻近关系，再结合通信日志核对实际接口。

尤其要区分空闲独占测试和共享网络下的训练。链路标称速度不等于该作业可用吞吐，NUMA 和网卡亲和也会引入额外路径。

同步等待#

参与者必须以兼容的顺序调用操作，并满足对应形状、精度和计数规则。某个 rank 在到达通信前读数据很慢，其他 rank 的等待会出现在 collective 区间，但根因可能不在通信库。

排查时按运行 ID 对齐各 rank 的时间线，查最早异常与首次顺序分歧。接口选择和权限也是条件，但不应跳过应用侧的一致性检查。

所有进程都活着，collective 也可能永远等不到#

若 rank 0 等待梯度 AllReduce，rank 1 却因分支进入下一次参数 AllGather，两个进程都存在也不能匹配完成。另一个常见轨迹是某 rank 先 OOM，其他参与者稍后才报告通信超时。

恢复日志应保留首错与后续连锁错误的顺序。把最后一条 timeout 当作首因，可能导致反复调整网络却从未修复内存或控制流问题。

通信量如何影响并行选择#

层内 TP 通信频繁，PP 在 stage 边界交换激活，分片训练会组装参数与归约梯度，EP 还需分发 token。比较方案应列每步调用次数、消息大小、参与组和物理路径。

同样一 GiB 数据，一次大传输与成千上万次小传输耗时不同；可重叠部分也不同。因此“总通信字节更少”是有用线索，却不足以单独决定最快配置。

Overlap 不是免费#

通信若能在不相关计算进行时启动，可以缩短关键路径。前提是后续计算暂不需要结果，且两者争用的资源不会抵消收益。通信 kernel 也可能消耗设备执行和内存带宽。

bucket 细分有助于更早启动，却增加固定开销；bucket 太大又会推迟开始。应比较完整训练步骤的耗时，不能只凭两条 trace 在时间上交叠就宣布加速。

大带宽为什么救不了大量小消息#

用教学近似 耗时 = 启动延迟 + 字节 / 吞吐。设固定开销 8 微秒、吞吐 40 GB/s，发送 4 KB 的数据项约 0.1 微秒，固定部分占主导；发送 40 MB 的数据项约 1 毫秒，带宽影响更明显。

真实 collective 有多轮交换，这里仅展示量级。若将大批内容切成许多极小 bucket，可能把 8 微秒反复支付。调优应同时观察启动次数与关键路径。

源码入口#

从 nccl/src/collectives.cc 看操作入队，再看 nccl/src/enqueue/。拓扑规划在 nccl/src/graph/，传输选择在 nccl/src/transport/，诊断相关代码可查 nccl/src/ras/。需要把模型切分与通信语义连接时，参考 megatron/core/tensor_parallel/mappings.py，先确认参与组与张量布局再深入设备实现。
