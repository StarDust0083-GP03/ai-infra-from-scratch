第 00 章

读前说明：不懂 CUDA 也能开始

源码快照 2026-09-22 · 约 8 分钟

一座档案馆准备开放两项服务：白天让读者询问馆藏资料，夜间用新增的校对文本训练模型。负责系统的工程师发现，模型文件能放进 GPU，服务却仍会排队；夜间作业拥有足够卡数，有时又停在通信步骤。这两件事会贯穿本书。

我们关心的对象有明确的尺寸和生命周期：一份权重在设备上驻留，一段上下文逐渐增加，一组梯度等待交换，一份检查点尚未写完。把这些对象和等待它们的进程对应起来，才能解释容量、速度与故障。

你不需要先会什么#

可以从普通 Python 程序和 HTTP 服务的经验出发。遇到 tensor 时，我们会数元素；遇到 collective 时，我们会写出各个参与者拿到什么；遇到 Kubernetes 时，我们只追踪一个资源申请如何落实到设备。无需先完成 CUDA 或分布式系统课程。

学习过程中也不用购买 GPU。纸上算例可以发现单位错误和资源约束，标准库实验可以检验调度规则。它们无法测出显存带宽、网络拥塞或真实模型的答案质量，后面会把这些限制写在对应实验旁边。

沿字节和等待连续读下去#

档案问答先把扫描材料转换成输入 token，模型读取输入，保存后续生成所需的状态，再逐步产出文字。每多接待一位读者，就可能多一份同时存活的 KV；每换一个并行方案，就可能改变这些状态存放在哪个 rank。

夜间训练还会保留激活、梯度和优化器状态。读到训练章节时，请继续追问同一个具体问题：这块内存要活到何时，哪个计算会消费它？到了集群章节，再给问题加上位置：它依赖的 GPU、网络和存储现在是否可用？

数字均带假设。书中的虚构硬件和负载只为便于核算，不代表档案馆真实部署，也不构成产品性能承诺。

本书怎么验证#

七个本地仓库承担不同的核对职责。阅读正文无需先打开它们；需要确认实现时，再按附录中的入口查找。

要核对的行为 对应资料
请求怎样获得 token 预算和 KV 块 vLLM
一步训练怎样组织计算与保存 TorchTitan
多个并行维度怎样组成进程组 Megatron-LM
集体通信怎样选择传输路径 NCCL
节点怎样向 kubelet 报告设备 NVIDIA Device Plugin
一组工作进程怎样取得启动资源 Volcano
控制器怎样维持分布式服务 KubeRay

本地快照支持“代码中存在这条路径”的判断；论文帮助解释算法；手算验证量纲；运行实验验证实验自身的行为。四种证据不能互相冒充。特别是读过某个 kernel 的代码，并不等于已经在目标设备上复现它的吞吐。

三条阅读路线#

第一次接触 AI Infra#

从请求经过的组件开始，读完单卡的字节账，再进入多卡通信。每章完成一个小动作：画一段时间线、算一份 tensor，或写出某个 rank 的输入输出。暂时跳过源码目录也不影响主线。

只想部署推理服务#

先定位首字等待和生成速度，再读显存、分页与连续批处理。随后补上加载、多卡和服务集群。若模型必须跨卡运行，通信章节也属于上线前知识，不能只调 HTTP 并发。

正在做训练平台#

从状态占用与训练循环入手，把数据位置、同步点和保存边界标到一步训练上。再读分片、作业队列和恢复。能启动一个作业只是起点，还需证明它在节点失败后能继续使用正确的数据与优化器状态。

图怎么看#

新版图解分别采用时间泳道、内存格子、输入输出矩阵和恢复状态机，不把所有问题都画成串联方框。图内的数量仅对应正文算例。

读图时分清三类连接：数据被搬到另一个位置，任务被安排执行，状态被持久保存。它们对延迟和恢复的影响不同。图中两条路径汇合，也不自动表示两边处于同一个事务。

示例的边界#

离线实验入口仍是：

python3 examples/infra_lab.py memory --parameters 3 --context 6144
python3 examples/infra_lab.py simulate
python3 examples/infra_lab.py check

计算器采用 GiB，除法分母是 2**30。模拟器的时间单位是调度轮，没有隐含“每轮等于几毫秒”。它使用人为给定的请求，演示预算、入队和释放，不复刻 vLLM 或任何 GPU。

如果你把公式用于实际采购，先换成目标模型配置，再补测工作区峰值、加载峰值与余量。显示很多小数位不会让缺失的开销自动出现。
