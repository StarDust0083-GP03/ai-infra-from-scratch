第 03 章

GPU 不是更快的 CPU

源码快照 2026-09-22 · 约 10 分钟

档案预处理程序逐文件解析复杂格式，模型计算却对大批规则数组执行相似运算。这两部分适合的处理器不同。把 Python 文件循环放到拥有 GPU 的机器上，不会使它自动变成并行设备计算。

一张卡里的四个角色#

计算单元#

执行单元擅长让许多数据使用相似指令，tensor core 对支持的矩阵运算提供专门路径。型号表中的峰值必须连同精度、稀疏性和运算口径阅读。模型未使用对应路径时，这个峰值不会转化为实际吞吐。

HBM 或显存#

设备要从这里读取权重与状态。容量是能同时保留多少内容，带宽是能多快搬出内容，两者不能互换。扩大容量可以放入更多上下文，却不保证每一步读历史状态的耗时更少。

Cache 与 shared memory#

较近的存储适合保存一小块反复使用的数据。kernel 通过分块避免同一内容反复往返大显存。FlashAttention 的 IO 优化可从这个角度理解：调整精确注意力的计算组织，减少中间结果的慢层级读写，而非用近似答案代替原问题。

互联#

主机和设备之间、设备彼此之间以及节点之间各有传输路径。请求跨越哪一条路径，要看实际进程和数据放置。机器有很多 GPU，并不保证任意两张卡间都拥有同样的带宽和延迟。

Roofline：先判断是哪种上限#

用目标精度的计算上限，与带宽乘算术强度所得上限比较，取较小者。算术强度是运算次数除以所选择存储层级的搬运字节数；分母口径必须一致。

这给出理想天花板，实际还会损失在启动、依赖、访存模式和并行度上。远低于两条上限时，不应立即宣布是“计算受限”，可能是数据或任务根本没持续送到设备。

用一个假设硬件手算 Roofline#

设有效带宽为 0.8 TB/s，计算平台为 64 TFLOP/s。强度为 20 FLOP/byte 时，带宽给出的上限为 16 TFLOP/s；强度为 160 时给出 128 TFLOP/s，但最终仍被 64 限制。转折点是 80 FLOP/byte。

图和数字不对应真实产品。把第一个任务换到仅提高计算峰值的设备上，其理想上限仍可能是 16；如果减少一半搬运而不增加运算，强度翻倍，才可能抬高这段上限。

为什么 Decode 容易带宽受限#

生成阶段常常只推进少量新位置，却需要访问大量模型权重和已有 KV。小 batch 下，一次权重读取服务的 token 少，复用不足，运算强度可能偏低。扩大活跃集合能够提高复用，但同时占用更多缓存和执行时间。

实际结果依赖架构与长度。长上下文的注意力读取也会变重，不能把所有 decode 都简化成只读权重。应在目标长度分布上查看 kernel 与内存流量。

CUDA 是什么层#

CUDA 提供设备编程、执行和库支持，上层框架借它提交 GPU 工作。主机通常把任务放入 stream 后继续运行，依赖关系决定哪些任务可重叠。第一次执行还可能有初始化、编译和图捕获，不能混入稳定阶段的计时。

allocator 保留的内存以及图执行需要的地址稳定性，同样属于这一运行环境。只观察 Python 变量是否消失，无法判断设备是否已完成工作或驱动是否收回空间。

异步提交为什么容易测出虚假的加速#

假设主机提交耗时 30 微秒，设备计算耗时 2 毫秒。只测调用返回可能得到接近 30 微秒，漏掉真正工作。单次设备耗时可用适当的 CUDA 事件测量，端到端延迟则需要在正确边界等待完成。

每个算子后强制同步虽然容易计时，却会破坏原来的重叠。比较方案前明确是在测单算子、完整步骤还是持续吞吐，并让两边采用同一口径。

看哪些硬件指标#

把指标配成问题一起看。设备占用高时，看单位时间完成的有效 token；HBM 流量高时，看是否重复读取或重算；设备空隙多时，看 CPU 供给与同步；频率下降时，检查功率、温度和硬件限制。跨卡步骤变慢，还要测必要互联的流量与等待。

显存占用只能描述容量，不能回答内存控制器是否繁忙。单一 utilization 曲线也无法分清有用矩阵运算和等待相关的 kernel。

第一条性能纪律#

为档案问答建一份固定负载说明：输入长度分位数、输出上限、请求到达方式、模型与精度、软件版本、卡型和拓扑。每次只改变有明确假设的一项，并同时保存延迟与吞吐结果。

卡一直忙，为什么请求还很慢#

如果某方案通过频繁抢占和重算让设备始终忙碌，读者仍可能迟迟等不到答案。比较完成请求数、有效输出 token、重算量与排队时间，才能判断利用率提高是否有收益。忙碌时间是资源消耗，交付结果才是工作产出。

来源入口#

硬件层级与计时限制可查 NVIDIA 的 GPU Performance Background、CUDA C++ Best Practices Guide 和 PyTorch CUDA semantics。Roofline 原始技术报告解释上界模型；FlashAttention 论文可用于核对注意力中的 IO 分块推导。使用资料中的数字前，先确认其设备、精度和实验条件。
