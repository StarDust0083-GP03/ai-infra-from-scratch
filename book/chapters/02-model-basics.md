# 最少模型知识：token、tensor 与参数

把一批档案送进模型前，需要回答两个量化问题：要处理多少位置，每个位置存多少数。模型术语在容量规划中最终都要落到这两个数量上。

{{diagram:tensor-shape|三份档案各取 512 个位置，每位置 2048 个数；先数元素，再按精度换算字节。}}

## Token 不是字，也不是固定长度

同样一份带旧地名、数字和标点的航海日志，不同 tokenizer 可能给出不同数量的 ID。按字符数设置输入限额只是入口保护，实际计算与计费应使用目标 tokenizer 的结果，包括聊天模板带来的额外位置。

输入 token 影响读取工作，输出 token 影响生成轮数，已经保留的位置影响 KV 占用。容量记录至少应把输入与输出分列；“总长相同”的两种请求不一定有相同延迟。

## Tensor 是带形状的数字数组

`[B, S, H]` 可以表示 B 份序列、每份 S 个位置、每位置 H 个隐藏数值。取 `[3, 512, 2048]`，共有 3,145,728 个元素。这里的三个维度描述一份中间结果，不等于模型拥有这些参数。

### 形状先决定元素数，精度再决定字节数

这份结果若使用 BF16，每元素 2 bytes，共 6,291,456 bytes，即 6 MiB；若改存 FP32，则为 12 MiB。换精度没有改变形状，增加序列长度才会改变位置数。

真实执行还可能存在转置、打包或临时副本。用形状乘元素字节数可求逻辑内容下界，要估峰值，还需确认这些副本是否同时活着，不能只看最后留下的那份结果。

## 参数是模型长期保存的 tensor

假设教学模型含 30 亿参数，按 16 位保存，权重下界为 `3e9 * 2 / 2**30`，约 5.59 GiB。请求变短并不会让这份权重同步缩小。

检查模型配置和权重文件比只看“3B”标签可靠。嵌入是否共享、量化元数据和保留高精度的层都会改变实际加载大小。文件在磁盘上的尺寸也不能直接替代运行时峰值。

## 数据类型决定字节和数值范围

| 表示 | 内容空间下界 | 规划时还要问什么 |
| --- | ---: | --- |
| FP32 | 4 bytes / 数 | 哪些累加与状态需要保留它 |
| BF16、FP16 | 2 bytes / 数 | 指数范围和舍入是否适合任务 |
| FP8 | 1 byte / 数 | 是否有匹配硬件、缩放与 kernel |
| INT8 | 1 byte / 数 | 缩放粒度与校准如何设置 |
| INT4 | 半 byte / 数 | 如何打包，额外元数据多大 |

半 byte 是逻辑记账方式，设备不必逐个半字节访问。低比特格式往往成组存储，并带尺度信息，实际字节数会高于这个下界。

### 参数量与请求长度分别让哪部分变大

同一个模型回答一句目录查询与处理整卷日志，权重不变，输入处理和历史状态不同。把模型换大则首先改变权重与每步计算；提高同时在线人数则增加并存的请求状态。定位显存增长时应记录究竟是哪一个维度发生了变化。

BF16 与 FP16 的存储尺寸相等，但可表达的范围不同。容量相同并不能推导出数值行为相同，精度切换后仍需检查溢出、异常值和任务输出。

## 层、头和隐藏维度

注意力会在多层保存 key 和 value。估算缓存时要知道层数、KV head 数以及每头维度。教学模型若有 24 层、4 个 KV head、每头 96 维，不能因为 query head 更多就把 KV head 也填成 query head 数。

这些值通常可从模型 config 查到。滑动窗口、混合注意力或其他架构可能使缓存规则不同，后文的公式会明确限定为常规全注意力情形。

## Batch 有两种含义

训练的一次更新可能累积多个 micro-batch，并由多个数据并行副本共同提供样本。在线推理的一个调度批次，则可能同时包含新输入块和已经开始生成的序列。

记录“batch 为 12”时，补写单位与范围：12 份样本、12 个活跃序列，还是 12 个 token？是每个数据副本、每卡，还是整个更新？缺少这些说明就无法复算资源需求。

## FLOP 与 byte 是两本账

一次矩阵计算既要执行运算，也要从存储取数。两种实现即使算出同一结果，也可能有不同的数据搬运量；同一个 kernel 在不同 batch 下又可能有不同复用。运算量除以搬运字节量得到算术强度，下一章据此判断可能的限制。

### 在线 batch 不应被理解为整齐的矩形

三位读者当前各保留 70、190 和 510 个位置。引擎可以用变长打包和块表描述它们，不必为每人都分配一个长度 510 的完整矩形。数学符号 `[B,S,H]` 帮我们理解维度，不能据此断言实际分配一定包含填充后的全部槽位。

## 一个练习

运行同一组输入，只改变权重精度：

```bash
python3 examples/infra_lab.py memory --parameters 3 --weight-bits 16 --context 6144
python3 examples/infra_lab.py memory --parameters 3 --weight-bits 8 --context 6144
```

权重下界应减半，KV 项应保持不变。再把上下文改为 12288，检查 KV 项加倍而权重不变。若你的结果不满足这两点，先查参数是否被误用，不急着解释硬件行为。
